# 报告设计与图表规则

## 1. 先定义读者动作

页面的完成标准不是“包含所有数据”，而是读者能快速回答：发生了什么、为什么重要、证据是什么、接下来做什么。

`report-plan.md` 至少包含：

- 受众与用途
- 数据范围、时间、单位、分母和缺失值处理
- 一句话核心结论与 2–4 个支撑判断
- 章节顺序和每章的读者问题
- 图表清单：问题、编码、口径、来源、替代文本
- 色彩、字体、宽度、间距和响应式策略
- 风险、限制与 missing evidence

## 2. 证据账本

| 类型 | 含义 | 页面表达 |
|---|---|---|
| Source fact | 输入中直接存在 | 给来源、日期或文件名 |
| Computed metric | 从输入计算 | 给公式、分母、单位和筛选条件 |
| Interpretation | 对事实的解释 | 使用“显示、提示、可能”等合适强度 |
| Recommendation | 基于证据的建议 | 连接到具体影响与优先级 |
| Missing evidence | 无法确认 | 明确写缺什么，不用占位数字 |

统计结果先做守恒检查、总和检查、范围检查和抽样复算。同比/环比必须写清基期；百分比必须写清分母；均值不可替代分布；相关性不可写成因果。

## 3. 信息架构

默认阅读顺序：

1. Hero：标题、范围、核心结论、必要元信息。
2. Executive summary：2–4 个判断，不是目录。
3. Evidence chapters：每章一个问题，先结论、再图、再解释和口径。
4. Detail：表格、分群、方法和异常值。
5. Actions：有证据支持的建议、优先级、负责人/时间（仅在输入支持时）。
6. Method & limitations：数据源、计算、更新时间和 missing evidence。

持续监控型 dashboard 才使用顶部过滤器、KPI 栅格和并列图表；一次性分析优先滚动叙事。

## 4. 图表选择

普通图表不够表达真实的数据关系时，再读取 [开源图表系统](open-source-chart-system.md)，从分布、排名、周期、层级、流向或多维 recipes 中选择。复杂图不能绕过该文件的“有趣门禁”和移动端降级规则。

| 要回答的问题 | 首选 | 避免 |
|---|---|---|
| 类别谁高谁低 | 排序条形图、点图 | 3D 柱、雷达图 |
| 随时间怎么变 | 折线图、小倍图 | 类别很多的面积图 |
| 构成是多少 | 100% 堆叠条、少量饼图 | 多环甜甜圈 |
| 两变量关系 | 散点图 + 注释 | 双轴图 |
| 分布如何 | 直方图、箱线图、点带 | 只给均值 |
| 流程/因果/结构 | 简洁流程图、关系图 | 没有真实关系的装饰图 |
| 精确查值 | 表格、热力表 | 用图逼读者猜数 |

图表标题应写可由图中证据支持的结论；副标题写范围、单位或比较基准。轴从零开始适用于长度编码；折线趋势可不从零，但必须清楚标注。不要截断轴来制造夸张差异。

## 5. 视觉系统

- 建议内容宽度：正文 `680–760px`，宽图/表 `1040–1200px`，页面最大 `1280–1440px`。
- 使用 8px 左右的基础节奏和 3–5 个字号层级。正文中文通常不低于 16px，行高 1.65–1.85。
- 页面 UI 默认使用中性色；图表拥有独立的数据色彩层。分类数据使用稳定的多色色板，连续数据使用单向色阶，偏离基准使用发散色阶，正负结果使用固定语义色；均需足够区分并兼顾色盲。
- 图表、注释、表格和正文共享 tokens。不要每章换一套配色。图表默认使用纯色；不要用全局纹理制造“无障碍感”，优先用直接标签、线型、点形、顺序和文本摘要建立冗余编码。
- 视觉元素必须承担 `structure / evidence / emphasis` 之一。无角色的装饰删除。
- 不使用左侧彩色竖线 callout、霓虹渐变铺满、玻璃卡片海、无意义大数字墙或伪品牌元数据。

## 6. 清晰表达

- 每段先写判断，再给证据；避免“从图中可以看出”之类空话。
- 数字按读者需要格式化，但保留精度边界。金额、比例和时间单位保持一致。
- 表格默认右对齐数字、左对齐文本，列名带单位，重要行可轻量强调。
- 注释紧贴对象；来源和口径靠近图表，不集中藏在页面末尾。
- 空状态、缺失值和样本过小要显式可见，不用 0 代替未知。

## 7. 响应式与可访问性

- 断点由内容决定，通常在 760–900px 将多栏重排为单栏。
- 移动端 KPI、图表和章节按阅读优先级重排；不要缩小到不可读。
- `<html lang>`、唯一 `<h1>`、语义 `<main>/<section>/<figure>/<table>`、键盘可达链接和可见 focus 必须存在。
- SVG 图表用 `role="img"` + `aria-label`，装饰 SVG 用 `aria-hidden="true"`；图表附短文本结论或数据表。
- 正文对比度目标 WCAG AA；颜色不能是唯一的状态或分类编码。
- `prefers-reduced-motion` 下停用非必要动画；打印样式移除导航和动效。

## 8. 截图验收

桌面 1440×900 与移动 390×844 都要检查：

- 页面无水平溢出，长表/代码只在自身容器滚动
- 字体已加载，图片无破图，图表标签和单位可读
- 无遮挡、裁切、孤行、断裂轴、错误图例或空白占位
- 首屏 2 秒内能识别主题、结论和范围
- 缩小预览后层级仍成立，灰度下重点仍清楚
- 截图为真实渲染结果，不是从 HTML 源码推断

超长报告可额外交付关键章节截图；全页截图仍用于整体回归。截图高度被工具限制时，要报告截断并分段捕获。
